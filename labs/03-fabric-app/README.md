# Lab 03 — Host the agent team in a Fabric app

**Goal:** a Rayfin (Fabric Apps) app with live charts from the lakehouse and the three data agents beside them, where the browser never sees a token, a secret or an agent URL.

**Time:** 40 minutes (the first `npx rayfin up` takes a few minutes).

## What's in the app

| Page | Data path |
| --- | --- |
| **Overview** — KPIs, net sales vs budget, regions, key accounts, delivery, forecast | Rayfin **lakehouse connector** (`fabric-sqlanalytics`, delegated: runs as the signed-in user) over three small tables in `lh__spaceparts.app` |
| **Agent team** — pick Sales Analyst, Operations or Planning, or ask the whole team at once | `askDataAgent` **Rayfin function** → the agent's **MCP endpoint** |
| **Pinned insights** — answers you kept | The app's own **Rayfin SQL database**, row-level policy `claims.sub eq item.user_id` |

Every Overview panel has "Ask …" buttons that open the agent team with the follow-up question: the report answers the questions you planned, the agents take the ones you didn't.

```
browser ──(question, agent key)──▶ Rayfin function askDataAgent ──(token)──▶ MCP: initialize → list tools → call ──▶ data agent ──▶ lakehouse
              ▲                                │
              └──── answer, identity, timing ◀─┘   (never the token)
```

## Files that matter

| File | What it does |
| --- | --- |
| `rayfin/functions/src/function_app.ts` | `askDataAgent(agent, question, conversation)` — validates input, picks the identity, returns the answer and which identity ran it |
| `rayfin/functions/src/data-agent.ts` | The MCP client: four JSON-RPC messages over `fetch` (plus the legacy Assistants path, auto-detected from the URL) |
| `rayfin/functions/src/agents.ts` | The agent team's MCP URLs (from `labs/01-data-agent/published-agents.json`) |
| `src/agent/index.ts` | **The seam.** The UI calls `askAgent()`; nothing else knows how agents are reached. `VITE_AGENT_MODE=offline` replays SQL-verified answers if the network fails |
| `src/agent/team.ts` | Agent names, roles and chips (the questions that passed evaluation) |
| `rayfin/connectors/spaceparts/*` | Connector entities over `app.sales_vs_budget`, `app.delivery_by_month`, `app.forecast_vs_budget` |
| `src/lib/connectors.ts` | Browser-side connector config (field-name arrays — a decorated entity class can't be bundled) |
| `src/queries/overview.ts` | Overview queries: server-side `groupBy` / `aggregate` through the connector |
| `rayfin/data/Insight.ts` | The app-owned table for pinned and saved answers |
| `fabric/build_app_tables.sql`, `fabric/deploy_app_tables.py` | Builds the three `app.*` Delta tables with a Spark notebook |

## Steps

1. **Prerequisites:** a workspace on F2+ capacity with *Fabric Apps (preview)* enabled, Node 20+, and Labs 01–02 done.
2. **Install:**
   ```powershell
   npm install
   cd rayfin/functions; npm install; cd ../..
   ```
3. **Point the app at your agents:** paste the three `mcpUrl` values from `labs/01-data-agent/published-agents.json` into `rayfin/functions/src/agents.ts`.
4. **Build the Overview tables** (once, and whenever the data changes):
   ```powershell
   python fabric/deploy_app_tables.py --workspace-id <ws> --lakehouse-id <lh> --lakehouse-name lh__spaceparts
   ```
   > Why tables, not SQL views? The connector reads through Fabric's GraphQL layer, which needs table metadata and rejects views.
5. **Connect the lakehouse** (already in `rayfin/rayfin.yml` for the reference workspace; for yours):
   ```powershell
   npx rayfin connector add --type fabric-sqlanalytics --name spaceparts --workspace-id <ws> --item-id <lh> --operations read
   ```
   Then set `auth.type: delegated` for the connector in `rayfin/rayfin.yml`, so charts run as the signed-in user, and keep the hand-written entities in `rayfin/connectors/spaceparts/`.
6. **Deploy:**
   ```powershell
   npx rayfin up --workspace-id <ws> --yes
   ```
   It creates the app item, the SQL database (`Insight`), the functions and the static site, and prints the URL.
7. **Choose the identity.** With no secrets set, the function uses Rayfin's **app identity** — the owner of the app item — and every user's question runs with the owner's permissions. To use the Lab 02 app registration instead:
   ```powershell
   npx rayfin secret set AGENT_TENANT_ID
   npx rayfin secret set AGENT_CLIENT_ID
   npx rayfin secret set AGENT_CLIENT_SECRET
   npx rayfin secret list        # names, never values
   ```
   Each answer shows **answered as app identity** or **answered as service principal**.
8. **Share:** give users *Run and interact* on the app item, and (because the connector is delegated) read access to the lakehouse.

## Offline fallback

```powershell
$env:VITE_AGENT_MODE = "offline"; npx rayfin up staticapp deploy
```

The agent team then replays the SQL-verified answers from `src/agent/recorded.ts` (generated by `labs/01-data-agent/make_ground_truth.py`), labelled as recordings. Unset it and redeploy to go live again.
